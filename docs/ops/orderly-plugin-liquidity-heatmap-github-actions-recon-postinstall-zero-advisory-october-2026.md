## <a id="read"></a>Read: proof-of-reach instrument, defender-relevant either way

The script's own comments argue this is an authorized-reach demonstration (everything is made *publicly visible* on purpose: step summaries, tags, committed reports — the opposite of exfil), and there is no secret-value theft in the artifact: key NAMES are inventoried, values are not read; the OIDC token is not captured. Three durable reads anyway:

1. **The capability map is a purchase-ready product.** One `npm install` inside a victim CI job: reads runner topology, proves OIDC mintability, writes to the default branch with the workflow token, and mints bot-attributed tags. 2. **The iteration clock tracks the curated lane, not the registry:** six versions in ~3 h, PR #1621 opened 15:22Z mid-iteration (after `1.0.4`, before `1.0.6`) — the author kept shipping AFTER being publicly filed, and the registry did nothing: at this check the name is LIVE at flagged-adjacent `1.0.6`, ZERO OSV + ZERO GHSA. 3. **The bot-identity write is the quietest artifact.** `github-actions[bot]` commits and force-pushed tags are invisible to humans who only watch PRs; detection needs `heatmap-setup-*` tag patterns, `heatmap-setup-report.json` path hits, and `chore: liquidity-heatmap setup cache` commit messages in repo/webhook logs.
