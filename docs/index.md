- [**Orkes Conductor CVE-2026-58138 pre-auth RCE under active exploitation** (Fortinet outbreak alert, THN Sep 19, 2026): CVSS **9.8** unauthenticated RCE in the Netflix-Conductor-based workflow-orchestration platform, **fixed in 3.30.2** (affected 3.21.21→before 3.30.2): crafted **inline workflow definitions with malicious JavaScript/Python expressions** hit the workflow API **before authentication**, and **unsandboxed GraalVM evaluators (`HostAccess.ALL` / `allowAllAccess(true)`)** let the script escape via Java reflection / subprocess calls — reachable through the ordinary **INLINE/LAMBDA/DO_WHILE/SWITCH** task types, i.e. the scripting features workflow authors use daily. Telemetry stack: **Fortinet 1,290 attempts blocked in one 24h window Sep 9 (+132% DoD), ~7,000 Sep 2–9**; Previdian honeypot attempts since **Jul 24**; Empirical Security ITW detection Aug 21 = probing predates the alert by 6+ weeks. Two compounding failures, both on-wiki patterns: **auth gap on a script-executing API** (mirror of Bifrost's register-runs-the-command) + **script engine and OS in the same trust domain** (Unit 42's "the shell tool is the perimeter"). Defender reads: patch to 3.30.2+; **audit GraalVM evaluator config regardless of version** — `HostAccess.ALL` is one auth bypass from OS code exec; workflow engines hold credentials by design, so a compromised Conductor is a credentials-forwarding foothold, not a web-server compromise. Not yet KEV; monitor for addition (Fortinet / The Hacker News, Sep 19, 2026)](ops/orkes-conductor-cve-2026-58138-preauth-rce-active-exploitation-fortinet-september-2026.md)

- [**WordPress "Click2Shell"** (pwn.ai, patched 7.1.1 on Sep 17, THN Sep 18, 2026): a crafted link opened by a **logged-in admin force-installs an attacker-chosen wp.org theme with ZERO clicks** — the wp.org API reads the link parameter as a plain theme slug and returns a REAL theme, while the admin page **reuses the raw attacker text inside DOM-selection code**, steering WordPress's own script to press Install; the admin's session supplies the nonce so **the attacker needs neither token nor permission**, and the theme sits **deactivated = nothing looks wrong**. Core bug alone can't take an arbitrary ZIP — RCE needs a **second flaw in the installed theme** (chain demonstrated) = wp2shell's "install the stage, another flaw runs it" playbook. Same two-parsers-one-string class as Netty/GitPython on-wiki. Defender reads: **installed-but-inactive themes are attack surface — diff `wp-content/themes` against an approved list, not the dashboard**; audit any admin UI interpolating URL values into selectors that gate privileged actions. No ITW reported (The Hacker News / pwn.ai, Sep 17–18, 2026)](ops/wordpress-click2shell-forced-theme-install-dom-selection-csrf-chainable-rce-pwnai-september-2026.md)

- [Hacktron AI "HEIF Heist" (Sep 18, 2026, WSJ + wide coverage): researchers chained a **libheif memory-corruption bug in a crafted HEIF/HEIC image upload to OpenAI's Discourse community forum** (server RCE) plus a **forum-to-account takeover flaw** to seize **employee ChatGPT/Codex accounts** — one employee's **Codex was connected to OpenAI's GitHub org**, so they reached internal repos and opened a PoC PR in the **monorepo**.
